Reproduce the complete study, step by step

This guide covers the current five-task, ten-seed study from real images through classifier fitting, evaluation, uncertainty analysis and table exports. It includes Windows PowerShell and Linux Bash, each with venv or conda. No files from an old author workspace are required by the main route.

How to use this guide

  1. Complete step 0 for your operating system.
  2. Choose exactly one setup in step 1: 1A, 1B, 1C or 1D.
  3. Follow steps 2-9 using only your shell's block at each step.
  4. Stay in the same terminal so interpreter functions remain defined. After reopening it, restore step 0 and the functions/paths for the existing environments; do not repeat environment creation.

The paper trains linear/cosine classifier heads and fits prototype banks on frozen representations. It does not pretrain or fine-tune ResNet18, DINOv2, UNI or CONCH. Published weights are prepared as inputs; training the paper's heads happens in step 6.

Three environments stay separate: head (Python 3.12), vision (Python 3.12, ResNet18/DINOv2) and pathology (Python 3.10, original UNI/CONCH). Step 1 defines three small functions that forward arguments to the right Python environment. Subsequent commands are the same for venv and conda within each shell; there is no need to switch activation or guess which python is on PATH.

0. Obtain a fixed source snapshot and choose outputs

Download/extract the full code release or clone the repository. Integrate the accompanying supplementary-export correction if it is not included. Run from the root containing src, scripts, configs, manifests and tests. Record git rev-parse HEAD when available, and record local updates separately.

Prerequisites: 64-bit Windows or x86_64 Linux, Git, network access, dataset/model access and disk/RAM for images, checkpoints, features and generated runs. Full fresh-run time and peak storage have not been measured in this audit. macOS/ARM is not a validated target for the supplied platform wheel locks.

For venv, install Python 3.12 and Python 3.10 with their matching venv support. A venv inherits the installed interpreter's patch version: the reference head interpreter is 3.12.3 and original foundation extraction used 3.10.22. Record any different patch version. The conda setup requests these versions explicitly. For conda, use a terminal where conda --version works. Creation uses Python/pip from conda-forge, followed by the repository's pip requirements; do not install a second conda NumPy/PyTorch stack afterward.

Use fresh output directories. artifacts/ is only a name for outputs derived from real data: features, fitted models, predictions and reports. Test fixtures are not scientific inputs. The main route uses no old author feature caches.

PowerShell:

$ErrorActionPreference = 'Stop'
Set-Location -LiteralPath 'C:\path\to\paper-code'
if (-not (Test-Path -LiteralPath 'scripts/run_experiments.py')) { throw 'Open the full repository root' }
$env:CBMP_FEATURE_DIR = Join-Path $PWD 'artifacts/features/full-reproduction'
$PathologyRequirements = 'requirements/pathology-cpu.txt'
$PathologyDevice = 'cpu'
New-Item -ItemType Directory -Force -Path artifacts/environment-records/full-reproduction | Out-Null

Bash/Linux:

set -euo pipefail
cd '/path/to/paper-code'
test -f scripts/run_experiments.py
export CBMP_FEATURE_DIR="$PWD/artifacts/features/full-reproduction"
CBMP_PATHOLOGY_REQUIREMENTS='requirements/pathology-cpu.txt'
CBMP_PATHOLOGY_DEVICE='cpu'
mkdir -p artifacts/environment-records/full-reproduction

Replace the example repository path above. Keep CBMP_FEATURE_DIR unchanged for extraction, fitting and prototype auditing. If repeating a full reconstruction, choose fresh feature/run/report/export directories consistently. The extractor will not replace an existing feature cache.

Native Linux paths differ from Windows paths. In WSL, a path such as D:\datasets\... is normally /mnt/d/datasets/...; native Linux uses its own mounts. Do not reuse a Windows venv in Linux/WSL.

Optional GPU choice for pathology

The default above is CPU. To select the original NVIDIA pathology stack, run the appropriate override below before step 2. Choose one stack per new environment; do not install the CPU and GPU requirements on top of each other.

PowerShell:

$PathologyRequirements = 'requirements/pathology-gpu.txt'
$PathologyDevice = 'cuda'

Bash/Linux:

CBMP_PATHOLOGY_REQUIREMENTS='requirements/pathology-gpu.txt'
CBMP_PATHOLOGY_DEVICE='cuda'

The original foundation run used Python 3.10.22, torch 2.0.1+cu117, torchvision 0.15.2+cu117 and a GTX 1660 Ti. The documented CPU requirements use a different torch pair. CUDA requires compatible existing hardware/driver support; these commands do not alter drivers. Record runtime/hardware changes and do not assume bitwise-identical features across them.

1. Create three environments: choose one option

Use new environment directories. If they already exist, restore their path and function definitions without recreating them, or choose new names. No command below clears an environment or installs into conda base.

1A. Windows PowerShell with venv

The py selectors use installed interpreters; confirm their versions.

py -3.12 --version
if ($LASTEXITCODE -ne 0) { throw 'Python 3.12 is required' }
py -3.10 --version
if ($LASTEXITCODE -ne 0) { throw 'Python 3.10 is required' }
py -3.12 -m venv .venv-review
if ($LASTEXITCODE -ne 0) { throw 'Head venv creation failed' }
py -3.12 -m venv .venv-vision
if ($LASTEXITCODE -ne 0) { throw 'Vision venv creation failed' }
py -3.10 -m venv .venv-pathology
if ($LASTEXITCODE -ne 0) { throw 'Pathology venv creation failed' }
$HeadPython = (Resolve-Path '.venv-review/Scripts/python.exe').Path
$VisionPython = (Resolve-Path '.venv-vision/Scripts/python.exe').Path
$PathologyPython = (Resolve-Path '.venv-pathology/Scripts/python.exe').Path
function Invoke-HeadPython {
    & $HeadPython @args
    if ($LASTEXITCODE -ne 0) { throw 'Head Python command failed; see the error above' }
}
function Invoke-VisionPython {
    & $VisionPython @args
    if ($LASTEXITCODE -ne 0) { throw 'Vision Python command failed; see the error above' }
}
function Invoke-PathologyPython {
    & $PathologyPython @args
    if ($LASTEXITCODE -ne 0) { throw 'Pathology Python command failed; see the error above' }
}

Continue at step 2. Activation is optional because the functions use explicit interpreter paths; no PowerShell execution-policy change is needed.

1B. Windows PowerShell with conda

The prefix environments live under the already-ignored .conda/ directory. conda run supplies the environment context, including Windows DLL paths. Do not replace it with an unactivated conda-prefix python.exe invocation.

conda --version
if ($LASTEXITCODE -ne 0) { throw 'Open a conda-enabled PowerShell terminal' }
$HeadPrefix = Join-Path $PWD '.conda/review'
$VisionPrefix = Join-Path $PWD '.conda/vision'
$PathologyPrefix = Join-Path $PWD '.conda/pathology'
conda create --override-channels --channel conda-forge --prefix $HeadPrefix python=3.12.3 pip=24.0 -y
if ($LASTEXITCODE -ne 0) { throw 'Head conda environment creation failed' }
conda create --override-channels --channel conda-forge --prefix $VisionPrefix python=3.12.3 pip=24.0 -y
if ($LASTEXITCODE -ne 0) { throw 'Vision conda environment creation failed' }
conda create --override-channels --channel conda-forge --prefix $PathologyPrefix python=3.10.22 pip=24.0 -y
if ($LASTEXITCODE -ne 0) { throw 'Pathology conda environment creation failed' }
function Invoke-HeadPython {
    conda run --no-capture-output --prefix $HeadPrefix python @args
    if ($LASTEXITCODE -ne 0) { throw 'Head conda command failed; see the error above' }
}
function Invoke-VisionPython {
    conda run --no-capture-output --prefix $VisionPrefix python @args
    if ($LASTEXITCODE -ne 0) { throw 'Vision conda command failed; see the error above' }
}
function Invoke-PathologyPython {
    conda run --no-capture-output --prefix $PathologyPrefix python @args
    if ($LASTEXITCODE -ne 0) { throw 'Pathology conda command failed; see the error above' }
}

Continue at step 2. No conda activate/deactivate switching is required.

3. Obtain and stage the real-image cohorts

3.1 PolypGen

Obtain the permitted v3 archive from the dataset's provider: PolypGen2021_MultiCenterData_v3.zip on Synapse. The dataset paper documents the release. Replace the local archive path below. Matching the filename is not sufficient: staging checks each selected image's recorded content hash.

PowerShell:

$PolypGenZip = 'D:\datasets\PolypGen2021_MultiCenterData_v3.zip'
Invoke-HeadPython scripts/stage_images.py --dataset polypgen --archive $PolypGenZip

Bash/Linux:

CBMP_POLYPGEN_ZIP='/srv/datasets/PolypGen2021_MultiCenterData_v3.zip'
head_python scripts/stage_images.py --dataset polypgen --archive "$CBMP_POLYPGEN_ZIP"

Expected: data/raw/polypgen/STAGED.json records 5,444 images from 37 sequences. Labels and group/center IDs come from the reviewed canonical manifest; this route does not independently repeat the original annotation review.

Download the pinned community redistribution with the vision environment's Hub client. This can fetch all matching parquet shards, not just selected patches. Dataset terms/provider access requirements still apply. The source/revision are preserved for the custom cohort actually used in the paper.

6. Plan, then actually train all heads and evaluate targets

The head environment performs source validation, candidate/temperature selection, linear/cosine training and prototype fitting/refitting on outer sources. Source choices are frozen before target prediction. --prepare-only validates inputs and writes run_manifest.json without training; the second command runs fitting. It does not load reference metric CSVs as a substitute for training.

PowerShell:

$StudyArgs = @(
    '--run-dir', 'artifacts/runs/full-reproduction',
    '--tasks', 'polypgen_resnet18', 'polypgen_dinov2', 'camelyon_resnet18', 'camelyon_custom_uni', 'camelyon_custom_conch',
    '--seeds', '17', '29', '43', '61', '89', '101', '131', '173', '211', '257',
    '--protocols', 'historical', 'matched4', 'factorial',
    '--workers', '1', '--threads', '4'
)
Invoke-HeadPython scripts/run_experiments.py @StudyArgs --prepare-only
Invoke-HeadPython scripts/run_experiments.py @StudyArgs --resume

Bash/Linux:

Restarting and troubleshooting

Situation Action
New terminal Restore step 0 with the same paths/mode and only the chosen setup's path/function definitions. Do not recreate environments.
Missing Python/venv Install the correct interpreters with venv support, or use conda. Do not substitute another major/minor version.
conda not found Use a conda-enabled terminal. The guide uses conda run, not global shell-activation changes.
Missing wheel/package Preserve the error; check OS, x86_64 architecture and interpreter version. Changed pins are a different software condition.
Provider 403/login failure Obtain UNI/CONCH approval and log in locally before retrying.
Image hash mismatch Check the exact dataset release/bytes. Do not edit canonical manifests to suppress it.
Feature file exists Preserve it; select a fresh CBMP_FEATURE_DIR. Interrupted extraction is not batch-resumable.
Interrupted fitting Repeat step 6's execution command with identical code, inputs, tasks, seeds and resource settings.
Stale RUNNING marker Verify that no worker remains active before handling a stale marker. Never remove a live run's lock.
Report/export exists Use a new destination and update all dependent commands consistently.
Only smoke completed Run the separate full ten-seed plan before aggregate audits and paper exports.

Changing tasks/seeds/resources requires a new run, not a modified resume. Use a new report/export directory for another analysis pass without deleting old data.

Conda-enabled shells can use conda activate ./.conda/review and conda deactivate. These activation commands are not needed by the explicit environment functions above.
